    01

    Indicator that slides to the active item

    Use it for the underline on a tab row or the bar beside a side nav. It replaces a script that measures the active item and writes a transform and a width.

    Try

    Click a tab in each demo. Then press the two buttons. The CSS bar keeps up with the label and the text size. The scripted bar stays where it was last measured.

    Snippet, HTML then CSS 
    <nav class="tabs">
  <ul>
    <li><a href="/overview" aria-current="page">Overview</a></li>
    <li><a href="/pricing">Pricing and billing</a></li>
    <li><a href="/docs">Docs</a></li>
  </ul>
</nav>
    .tabs { anchor-scope: --active; }

.tabs ul {
  position: relative;
  display: flex;
}

.tabs [aria-current="page"] { anchor-name: --active; }

.tabs ul::after {
  content: "";
  position: absolute;
  position-anchor: --active;
  inset-block-end: 0;
  inset-inline-start: anchor(start);
  inline-size: anchor-size(inline);
  block-size: 2px;
  background: currentColor;
}

@media (prefers-reduced-motion: no-preference) {
  .tabs ul::after {
    transition:
      inset-inline-start 0.25s ease-out,
      inline-size 0.25s ease-out;
  }
}
    Support
    Chrome 131 / Firefox 147 / Safari 26. The limit is anchor-scope.
    Without it
    The anchor() declarations are dropped and the bar has no width, so it does not show. The active tab keeps its color. Firefox places the bar but does not slide it, according to MDN.
    Stripe
    .hds-side-nav__link[aria-current]{anchor-name:--active-nav} and .hds-side-nav__list:after{inset-block-start:anchor(top);height:anchor-size(height);position-anchor:--active-nav}, in the home page bundle c27cf5158235e02f.css.
    Caveats
    No page I fetched renders that side nav. I saw the rules and not the component running on Stripe. Two navs need anchor-scope, or both bars follow the last active item.
    My call
    AddIt removes a measuring script, all three engines have it, and it fails to nothing.
    02

    Styles that apply only when a scroller overflows

    Use it on any row that may or may not fit, such as tabs, a toolbar or a table wrapper. It replaces a ResizeObserver that compares scrollWidth with clientWidth.

    Try

    Drag the slider to make the box narrower. The fade appears when the row stops fitting. Then scroll the second row to either end.

    Snippet 
    @keyframes overflowing {
  from, to { --fade: 2rem; }
}

.scroller {
  --fade: 0px;
  overflow-x: auto;
  animation: overflowing linear;
  animation-timeline: scroll(self inline);
  mask-image: linear-gradient(
    to right,
    transparent,
    #000 var(--fade),
    #000 calc(100% - var(--fade)),
    transparent
  );
}

/* Per edge: fade only the side that still has content */

@property --fade-start {
  syntax: "<length>";
  inherits: false;
  initial-value: 0px;
}

@property --fade-end {
  syntax: "<length>";
  inherits: false;
  initial-value: 0px;
}

@keyframes edges {
  from { --fade-start: 0px; --fade-end: 2rem; }
  10%, 90% { --fade-start: 2rem; --fade-end: 2rem; }
  to { --fade-start: 2rem; --fade-end: 0px; }
}

.scroller-edges {
  overflow-x: auto;
  animation: edges linear;
  animation-timeline: scroll(self inline);
  mask-image: linear-gradient(
    to right,
    transparent,
    #000 var(--fade-start),
    #000 calc(100% - var(--fade-end)),
    transparent
  );
}
    Support
    Chrome 115 / Firefox Nightly only / Safari 26 for animation-timeline. The mask works everywhere.
    Without it
    The row scrolls with no fade.
    Stripe
    @keyframes detect-scroll{0%,to{--can-scroll: }} and .navigation-menu{animation:detect-scroll linear;animation-timeline:scroll(inline self)}, in 5abff0f798ddf7af.css. Seen live: at 1100px the German home page nav overflows and flips to overflow-x: hidden and flex-direction: row-reverse. The English one fits and does not.
    Caveats
    Firefox is the gap. The scroll-driven reveal under "Next" in PRACTICES.md waits on the same one. Stripe stores an empty value and reads it through a fallback. My version sets real values in the keyframes and tested the same. animation-timeline must come after animation.
    My call
    AddThe fallback is a plain scroller, and it removes a ResizeObserver.
    03

    Transition a custom property with @property

    Use it when one state change should drive several values together, or when a script feeds a number such as pointer position into CSS and the result should ease.

    Try

    Hover each card, or tap its button. On the left one number eases and the arrow, the bar and the text follow it. On the right the same rules snap. Then move the pointer over the two panels below.

    Snippet 
    @property --progress {
  syntax: "<number>";
  inherits: true;
  initial-value: 0;
}

.card:focus-within { --progress: 1; }

@media (hover: hover) {
  .card:hover { --progress: 1; }
}

.card .icon { rotate: calc(var(--progress) * 90deg); }
.card .bar { scale: calc(0.25 + var(--progress) * 0.75) 1; }
.card .more { opacity: var(--progress); }

@media (prefers-reduced-motion: no-preference) {
  .card { transition: --progress 0.4s ease-out; }
}
    Support
    Chrome 85 / Firefox 128 / Safari 16.4.
    Without it
    The value flips at once. The end states are the same.
    Stripe
    @property --hover-progress{syntax:"<number>";initial-value:0;inherits:true} with transition:--hover-progress .6s, in the home page bundle e5be0f41b7fa7f3f.css. On /contact/sales, --gradient-border-mouse-x is a <length-percentage> that feeds a radial gradient.
    Caveats
    A registration is global, so names must be specific. That a script writes the pointer position on Stripe is my inference. I did not read their script.
    My call
    AddAll three engines have had it since 2024 and nothing in the list covers it.
    04

    One box-shadow built from independent layers

    Use it on inputs, buttons and cards that combine a hairline border, a focus ring and elevation. Each state sets its own layer and none of them overwrites another.

    Try

    Hover each field, then click into it. On the left the border, the ring and the elevation show together. In the middle the nested box picks up its parent's border and shadow. On the right, focus wipes out the border and the elevation.

    Snippet 
    @property --keyline {
  syntax: "*";
  inherits: false;
  initial-value: 0 0 0 0 transparent;
}

@property --ring {
  syntax: "*";
  inherits: false;
  initial-value: 0 0 0 0 transparent;
}

@property --elevation {
  syntax: "*";
  inherits: false;
  initial-value: 0 0 0 0 transparent;
}

.surface {
  box-shadow: var(--keyline), var(--ring), var(--elevation);
}

.field { --keyline: 0 0 0 1px oklch(0.8 0 0); }
.field:hover { --keyline: 0 0 0 1px oklch(0.6 0 0); }

.field:focus-visible {
  --ring: 0 0 0 4px oklch(0.7 0.15 250 / 0.5);
  outline: 2px solid transparent;
}

.raised { --elevation: 0 4px 12px oklch(0 0 0 / 0.15); }
    Support
    Chrome 85 / Firefox 128 / Safari 16.4.
    Without it
    The variables are undefined and the whole box-shadow drops. I checked this in Chrome by removing the three registrations.
    Stripe
    Inline styles on docs.stripe.com: box-shadow: var(--s--top-shadow), var(--s--keyline) 0 0 0 var(--s--keyline-width), var(--s--focus-ring), var(--s--box-shadow), with 40 @property rules. Seen live: 35 of 87 links, buttons and inputs computed a four-layer shadow.
    Caveats
    Entry 20 draws the focus ring with outline. This draws it with a shadow and keeps a transparent outline for forced-colors mode. Tailwind's ring and shadow utilities already compose this way, so it adds little there.
    My call
    MaybeStrong in a hand-written design system, redundant where Tailwind is in use.
    05

    Whole card clickable from one link

    Use it for cards, list rows and tiles where the whole area should navigate. It replaces a link wrapped around the card and a click handler on a div.

    Try

    Click the text, the corner and the Save button of the left card and watch the line under it. Then press Tab until focus reaches each card. On the left the ring is on the card and Save is its own stop.

    Snippet, HTML then CSS 
    <article class="card">
  <h3><a class="card-link" href="/reports/q3">Quarterly report</a></h3>
  <p>Revenue grew in every region.</p>
  <button type="button">Save</button>
</article>
    .card { position: relative; }

.card-link::after {
  content: "";
  position: absolute;
  inset: 0;
}

.card-link:focus-visible { outline: none; }

.card:has(.card-link:focus-visible) {
  outline: 2px solid currentColor;
  outline-offset: 2px;
}

.card :is(button, a:not(.card-link)) {
  position: relative;
  z-index: 1;
}
    Support
    Chrome 105 / Firefox 121 / Safari 15.4, for :has().
    Without it
    No current browser lacks :has(). An old one would lose the focus ring, because the link's own outline is switched off.
    Stripe
    .hds-resource-card__link{position:absolute;inset:0;z-index:2} and .hds-resource-card:has(.hds-resource-card__link:focus-visible){outline:var(--hds-focus-outline)}, in c27cf5158235e02f.css. Seen live on /billing: the link's box equals the card's, 400 by 215.5px.
    Caveats
    Stripe stretches the link itself. I stretch its ::after, Heydon Pickering's form, so the link text stays in the flow. Text under the overlay cannot be selected.
    My call
    AddA common need, it works everywhere, and it is better for screen readers than the wrapper.
    06

    Reveal with clip-path

    Use it for dropdowns, menus and panels that open over the page and whose height is not known. It unrolls the panel without animating height, in every browser.

    Try

    Open and close both menus a few times. The left one unrolls at an even pace and keeps its shadow. The right one opens too fast and waits before it closes, because its transition runs over 40rem of height it does not have.

    Snippet 
    .menu {
  clip-path: inset(0 -3rem 100%);
  visibility: hidden;
}

.menu.is-open {
  clip-path: inset(0 -3rem -3rem);
  visibility: visible;
}

@media (prefers-reduced-motion: no-preference) {
  .menu {
    transition:
      clip-path 0.25s ease-out,
      visibility 0.25s;
  }
}
    Support
    Chrome 55 / Firefox 54 / Safari 12.1.
    Without it
    Every current browser has it.
    Stripe
    .hds-navigation-menu__popup{clip-path:inset(0 -60px 100% -60px round …)} and [data-status=open]{clip-path:inset(0 -60px -60px -60px round …)}, in 5abff0f798ddf7af.css. Seen live: the Products menu opens with a 0.2s clip-path transition and its height reads 698px the whole time.
    Caveats
    Only for panels that overlap the page. In the normal flow a closed panel leaves a gap, so an accordion still uses entry 4. The visibility part is my addition. Stripe opens the menu from a script.
    My call
    AddIt works everywhere, needs no height, and Stripe's own fallback was the max-height trick on the right.
    07

    Shadow change that fades and does not repaint

    Use it on cards that lift on hover, most of all in a grid of many cards or with a large blur.

    Try

    Hover each card, or press the button. They look the same, and that is the point. The difference is how much the browser paints, which the bars show.

    The bars are my measurement and do not update live. I traced one change in and one change out, 0.3s each, twice, in Chrome 150 on 2026-10-01. A page cannot count its own paints.

    Snippet 
    .card {
  position: relative;
  isolation: isolate;
}

.card::before,
.card::after {
  content: "";
  position: absolute;
  inset: 0;
  z-index: -1;
  border-radius: inherit;
  pointer-events: none;
}

.card::before {
  box-shadow:
    0 1px 4px oklch(0.3 0.05 250 / 0.1),
    0 2px 10px oklch(0.3 0.05 250 / 0.08);
}

.card::after {
  box-shadow:
    0 4px 8px oklch(0.3 0.05 250 / 0.06),
    0 12px 32px oklch(0.3 0.05 250 / 0.16);
  opacity: 0;
}

@media (hover: hover) {
  .card:hover::before { opacity: 0; }
  .card:hover::after { opacity: 1; }
}

@media (prefers-reduced-motion: no-preference) {
  .card::before,
  .card::after { transition: opacity 0.3s ease; }
}
    Support
    Every browser.
    Without it
    Does not apply.
    Stripe
    .hds-resource-card:before{box-shadow:var(--hds-shadow-xs);opacity:1} and .hds-resource-card:after{box-shadow:var(--hds-shadow-md);opacity:0}, in c27cf5158235e02f.css. Seen live on /billing: the card has no shadow of its own, and hover swaps the two opacities.
    Caveats
    It takes both pseudo-elements of the card, so it cannot share an element with entry 27. The saving was about 2ms of paint per card per hover. That Stripe does it for paint cost is my inference.
    My call
    MaybeWorth it for a grid of cards. For one card the plain transition is fine.
    08

    Label centered on its letters with text-box

    Use it on single-line labels in buttons, badges and chips, so equal padding looks equal in any font.

    [ Where this stands ]

    PRACTICES.md lists * { text-box: trim-both cap alphabetic } under "Left out on purpose". That rule trimmed every text block on the page. A one-line paragraph went from 25px tall to 11px.

    This candidate is the scoped version. It is one declaration on the single-line labels you pick, and their padding is set with the trim in mind. Nothing else on the page changes, so the earlier decision stands either way.

    It is already in PRACTICES.md as entry 33. It was added while this page was being built, with a second rule for a button that holds an icon. A yes here keeps it. A no means it should come out again.

    Try

    The orange bands are the space above the capitals and below the baseline. Change the font. On the left the two bands stay equal. On the right they drift apart, and the third button shows the declaration doing nothing on a flex container.

    Snippet 
    .button {
  display: inline-block;
  padding: 0.75rem 1.25rem;
  text-box: trim-both cap alphabetic;
}
    Support
    Chrome 133 / Firefox 154 / Safari 18.2.
    Without it
    The label keeps its normal line box. If you raised the padding to suit the trimmed label, the button is taller there.
    Stripe
    .hds-button{display:inline-flex;text-box:trim-both cap alphabetic}, in c27cf5158235e02f.css, next to a padding of 15.5px above and 16.5px below.
    Caveats
    Stripe's own declaration is inert. Their button is a flex container, and switching text-box off on 13 buttons changed no height. I infer the intent from the declaration. The gain is small, from nothing to 1.7px at 16px depending on the font, and the button gets shorter, so the padding has to be set again. It is already entry 33.
    My call
    MaybeReal but small. It pays off with a brand font whose metrics are uneven. I would not have added it ahead of your call.

    Decisions

      Two surprises in Stripe's own CSS

      The text-box declaration on Stripe's buttons does nothing. .hds-button is a flex container, and text-box has no effect on one. I switched it off on 13 buttons on the home page and no height changed. The uneven padding, 15.5px above and 16.5px below, does the centering.

      @media (prefers-reduced-motion: reduced) ships on /payments and /pricing. reduced is not a valid value, so the rule never applies and the mobile menu keeps its motion. Opt-in motion, as in entry 22, cannot fail this way.

      Also worth knowing: Stripe uses no oklch(), no light-dark() and no prefers-color-scheme. Colors are hex tokens and dark sections use a class.

      Looked at and rejected

      Covered by an existing entry

      • Accordion. ::details-content with allow-discrete and an interpolate-size branch. Same as entry 4.
      • Hover gating. (hover: hover) and (pointer: fine). Entry 21. The older system also gives touch a pressed state with (pointer: coarse) { :active }. Entry 31 is press feedback.
      • Reduced motion. 55 no-preference queries against 12 reduce on the home page. Entry 22.
      • Focus. A 3px translucent outline with a 3px offset on :focus-visible. Entry 20.
      • Tabular numbers. Entry 28. Stripe adds a tight variant with letter-spacing: -0.03em, which could be one more line there.
      • Container queries, subgrid, logical properties, scroll snap, overflow: clip, scrollbar-gutter, html:has(…) scroll lock. All present, all in entries 9, 12, 13, 16, 17 and 18.
      • Popover placement. anchor() with side and alignment set by a script. Entry 26 needs no script.

      Not at the level of properties and values

      • Cascade layers. @layer reset, base, app with :where() 109 times. It is stylesheet architecture, and Tailwind and StyleX manage the cascade their own way.
      • The layout grid. 4, 8 and 12 columns with span tokens that change at breakpoints. The older grid depends on a script-measured scrollbar width. Entry 1 needs neither.
      • Type and spacing scale. Fixed rem tokens redeclared at 640px and 940px. A breakpoint ladder, which entry 7 replaces.

      Brand design, or behind the list already

      • Color. Hex tokens, a .hds-mode--dark class, color-mix() in sRGB. Entries 2 and 8 are ahead of it.
      • Shadow tokens. Two blue-tinted layers per elevation. Sound, but it is their look.
      • Easing. Two curves cover most of it and there is no linear(). Entry 30 has motion tokens.
      • Gradient border and spinner. mask-composite: exclude over a conic gradient. Decoration. The reusable part is candidate 3.
      • Card that grows on hover. An oversized layer whose clip-path animates. A one-off. The mechanism is candidate 6.

      Too narrow or too fragile

      • Bottom-sheet dialog. Scroll snap with a named scroll timeline that fades the overlay. It still needs a script, and Firefox has no scroll timelines.
      • :lang() type overrides. Weight changes for Japanese and Chinese, specific to their font.
      • @font-face inside @media. font-display: block on wide screens and swap on narrow ones.
      • Real superscripts. font-feature-settings: "sups". Works only when the font has the glyphs.
      • Half-pixel nudges and per-browser color patches. Hand tuning behind min-resolution, @-moz-document and -webkit-touch-callout.
      • Sail's support test and font-metric tokens. Workarounds for browsers before @property and text-box.

      The full list with reasons and URLs is in research/stripe.md.

      Every demo was tested in Chrome 150. Safari and Firefox support comes from MDN browser-compat-data, read on 2026-10-01.
